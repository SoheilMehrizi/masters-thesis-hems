JevAgentHarness: Benchmarking, Deploying and Training
Decision Models That Share Control with LLMs
Kunlun Zhu1, Tao Feng1, Xu Han1, Heng Wang1,
Ling Yang2, Xiangru Tang3, Jiaxuan You1, Heng Ji1
1University of Illinois Urbana-Champaign 2Princeton University 3Google
Abstract
Large language model (LLM) agents now fix
software, operate computers and serve cus-
tomers, but their harnesses, the programs that
run them, call a large LLM at every step, which
makes long tasks slow and costly. Most of
these calls end in a multiple-choice decision,
such as which tool to call next. Decision mod-
els such as JEV answer these questions directly,
at a fraction of an LLM call’s time and price.
We ask how a harness can delegate these de-
cisions to a decision model with little loss of
success. To evaluate decision models in agen-
tic tasks, we build AGENT DECISION BENCH ,
which tests them from isolated questions up to
control of a running agent, on public bench-
marks and our DECISION GYM environment.
The decision model most accurate on isolated
questions solved only 69.5% of agent tasks,
and without a fitted confidence threshold, del-
egating tool choices lowered success by 19.0
points. Building on these findings, we then
design JEVAGENT HARNESS , which fits this
threshold for each choice on the agent’s own
trajectories and lets the LLM decide below it.
Because existing decision models never see the
states an agent reaches after its own mistakes,
we train AGENT DECISION -4B , an open 4B
model, on such states with JEV’s answers as la-
bels. On tasks unlike its training data, the agent
solved 91.5% of them with AGENT DECISION -
4B and 82.0% with JEV. On tasks like their
training data, 4B models trained this way made
agents 81.1–89.0% cheaper and up to 2.5
times faster, without losing 3 or more points
of task success. The models, data, and har-
ness will be released athttps://github.com/
JevAgentHarness/JevAgentHarness.

Decision models such as JEV (Almeida, 2026)
and its open counterparts (InternLM, 2026;
StartLuxLabs, 2026; razorback16, 2026) make
such choices directly. Given the task, the history
and one multiple-choice question, a decision model
returns a probability for each listed option instead
of generating text, much like the fast, intuitive Sys-
tem 1 rather than the slow, deliberate System 2
(Kahneman, 2011). In one recorded episode, a call
to JEV took 28% of an LLM call’s time and 2.6%
of its price. Existing systems use decision models
for game actions, memory, escalation and judging
(Ma et al., 2026; Jiang et al., 2026; Wu and Lim,
2026b; Li et al., 2026). Because a harness lists the
actions at each step, it can delegate a choice to a
decision model when that model is confident and
otherwise defer to the LLM (Figure 1). We call this
decision modeling for agents (Chen et al., 2025).
Decision models, however, are built and tested
on fixed questions and do not adapt to the agent
they serve. Whether one works inside an agent has
not been tested. Routers and cascades (Chen et al.,
2024; Ong et al., 2025), small function-calling mod-
els (Zhang et al., 2025c; Lin et al., 2025) and fast–
slow agents (Lin et al., 2023; Christakopoulou et al.,
2024) also move work away from the large model,
and they too have been tested on fixed questions or
on a single kind of choice, and agent benchmarks
score only whole tasks. Inside an agent, a decision
model’s mistakes carry over to later steps (Zhu
et al., 2025), and one choice changes the next. It
also faces states that follow the agent’s own errors,
which fixed question sets rarely contain, and every
query to it adds latency. We therefore ask:
How can an agent harness delegate routine
choices to a fast, cheap decision model when
the model is reliable, so that agentic tasks
become faster and cheaper with little loss of
success?
Our hypothesis is that a decision model helps an
agent when it is chosen by tests inside the agent,
used only when it is confident, and trained on the
states that the agent itself reaches. We build one
part for each of these three conditions (Figure 2).
AGENT DECISION BENCH tests decision models
at three levels, each closer to real use: on isolated
questions with no agent around, at each step of
recorded agent runs, where answers are scored but
not carried out (step level), and in control of a
running agent, where each choice changes what
comes next (task level). We use public bench-
marks and DECISION GYM, an environment we
built that knows the acceptable next steps at every
state, so that each choice can be scored. JEVAGEN -
THARNESS lets an existing harness put each rou-
tine choice to a decision model as a typed multiple-
choice question and uses the answer only when the
model’s confidence clears a threshold fitted on the
agent’s own trajectories. AGENT DECISION -4B is
an open 4B decision model that learns from JEV’s
answers on the states the agent visits. We will re-
lease all three. AGENT DECISION -4B chooses bet-
ter than JEV inside the agent: on tasks unlike its

2 Where and How to Delegate
Whether a choice is worth handing to the decision
model depends on which choice it is and on how
the decision model’s answer is combined with the
LLM’s. We define the task (Figure 3) and derive a
rule for what to delegate (§2.1). The setup applies
to any harness that can list its options at a step.
Decision points. An episode is one agent run on
a task, and its state s holds what the agent knows
at a step. A decision point d is a kind of choice
that recurs across steps and whose options Od(s)
the harness can list. We study eight decision points
(Figure 3a). Three choose what the agent does:
the tool, its arguments and, without tools, the next
action. Five control the loop: whether to write
memory, reflect after a failure, stop, or route the
step to a cheaper LLM, and which stored notes to
read back.
Decision models. A decision model reads s as
text with one question and its options (App. B.3)
and returns a probability p(o | s) for each option.
Its answer is the likeliest option, and its confidence
c(s) is that option’s probability ( JEV (Almeida,
2026) returns this probability directly). Open mod-
els like Intern-Decision and AGENT DECISION -
4B score all options in one forward pass.
Who decides. An integration mode fixes who
proposes an answer and who has the last word (Fig-
ure 3b). We mostly use the cascade ( CASCADE ):
the decision model answers first, and the harness
uses it when its confidence clears a threshold,
c(s) ≥ τd. Otherwise the LLM decides as usual.
In the other modes, the decision model always de-
cides ( REPLACE ), shortlists options for the LLM
( ASSIST ), approves or rejects the LLM’s choice
( GUARD ), or decides whether an optional step
such as reflection runs ( TRIGGER ). We imple-
ment all 40 point–mode combinations (App. A).
A decision point with its mode and threshold is a
delegation, such as the tool-choice cascade. We
seek the cheapest set of delegations whose success
stays within 3 points of the LLM alone.
A decision-making example. Consider a
customer-service agent asked to cancel an order
(App. Figure 6). At each step, the harness asks
which of 69 tools to call. At step 3, JEV split
its vote between asking the customer (0.63) and
cancelling (0.37), so the LLM decided and asked.
At step 4, JEV was confident about cancelling
the order. JEV then chose the order from options
copied from the chat and the reason from a fixed
list. Both answers were confident, so the call ran
without the LLM. An unsure answer or a free-text
argument would cost one LLM call.
2.1 Deciding what to delegate
A threshold rule. Handing a choice to the deci-
sion model can save an LLM call but may lead to
a wrong choice. If its confidence equals its chance
of being right (App. A), handing over is worth it
exactly when c(s) ≥ qL −∆C/V , where qL is how
often the LLM gets this choice right, ∆C the price
of the saved call and V the cost of a wrong choice.
This value is the best threshold τd. The decision
model may thus be a little less accurate than the
LLM as long as the saving covers the extra risk.

Fitting thresholds. We first run the agent on sep-
arate tasks (150 per agent LLM) while the decision
model answers every question silently ( shadow
mode). From these trajectories we estimate, per
decision point, how often the LLM was right (qL),
a call’s price (∆C) and V , the drop in task success
after one wrong choice, valued at $1 per solved task.
The trajectories also give the decision model’s ac-
curacy at each confidence, so the threshold is the
lowest confidence above which accepting is worth
it, and the confidence need not match its exact
chance of being right (App. A). If none qualifies,
the LLM keeps deciding. With JEV and Flash, the
fitted thresholds were 1.00 for tools and 0.99 for
arguments, so only near-certain answers are used.
3 A GENT DECISION BENCH
A decision model can score well on a test and still
fail inside an agent. Existing tests ask single ques-
tions with fixed answers, so a wrong answer never
affects what happens next. Agent benchmarks run
whole tasks but report only whether a task suc-
ceeded, without showing which choice went wrong.
AGENT DECISION BENCH tests decision models at
three levels on public data and on DECISION GYM,
with every call priced and timed (App. F, Table 5).
L1: isolated questions. The decision model an-
swers single questions with no agent around it.
We turn the 1,114 tool-choice and 1,949 argument
items of BFCL v4 (Patil et al., 2025) and the 928
When2Call items (Ross et al., 2025) into multiple-
choice questions.
L2: step level, on recorded agent runs. The
decision model answers at each step of recorded
agent runs, but its answer is only scored, so the
run continues as recorded and one mistake can-
not cause the next, as when driving policies are
tested on recorded drives. Each answer is checked
against an answer key of acceptable next steps. All
models answer the same 5,314 states of 200 new
DECISION GYM tasks (the common states).
L3: task level, in control of the agent. The de-
cision model now makes every tool choice of a
running agent (every action in ALFWorld) with no
threshold, while the LLM writes the arguments,
and each choice is carried out. A wrong choice
changes what the agent sees next, so mistakes
can pile up. This level measures task success.
It is the hardest level and the closest to deploy-
ment. Our agent loop runs τ 2-bench (Barres et al.,
2026), ALFWorld (Shridhar et al., 2021) and DE-
CISION GYM tasks, and hooks let us test exist-
ing harnesses without changing their code: mini-
SWE-agent and SWE-agent on SWE-bench Ver-
ified (Jimenez et al., 2024), and the pi terminal
agent on Terminal-Bench 2.0 and Terminal-Bench-
Science (Merrill et al., 2026; Terminal-Bench-
Science Team, 2026).
Levels 2 and 3 need an environment that knows
which next steps are acceptable at every state an
agent can reach, including after its own mistakes.
Public agent benchmarks check only the final state
or the progress of a run (Lu et al., 2025; Ma et al.,
2024), have a fixed set of tasks and are slow and
costly to rerun. We therefore built DECISION GYM,
a simulated customer service desk for a small shop,
with typed tools over a small database as inτ-bench
(Yao et al., 2025) and requests from templates as
in TextWorld (Côté et al., 2019). Every task of-
fers the same 68 tools plus finish in shuffled order:
seven core tools, one that asks the customer, 31
near-duplicates of core tools and 29 unrelated ones.
Because each task comes from a scripted plan, DE-
CISION GYM derives an answer key at every reach-
able state from which the task can still be solved,
even after detours. Training, threshold fitting and
testing use disjoint random seeds. Near-duplicate
distractor tools and must-ask states, where the right
move is to ask the customer, make the tasks hard.
The answer key is hidden from all models, and in
strict mode any change to the shop’s data that is
not in the plan ends the episode (App. B). Two
further task sets, added after the main study, test
the models beyond their training data. Shifted
tasks (DECISION GYM-Shift, App. G.9) rename the
tools and change the wording and kinds of requests.
Hard tasks (DECISION GYM-Hard, App. D.6) have
10 or 12 customers each and a new rule for can-
celling or shipping.
4 J EVAGENT HARNESS
JEVAGENT HARNESS moves a harness’s routine
choices to a decision model. It poses each listed
choice as a multiple-choice question and uses the
answer only when the model is confident enough.
Otherwise the LLM decides as usual. The harness
has three parts (App. Figure 8).
A typed decision interface. Every choice uses
JEV’s input format, whose options are the tools,
fixed-list or yes/no argument values, or text spans
to copy from the context. A tool call is split into a

tool choice and one choice per such argument, so
the decision model can pick both while the LLM
writes only free text. Any model that accepts this
format can be used (App. C).
A confidence threshold fitted on trajectories.
Each decision point gets the threshold of §2.1, fit-
ted on shadow-mode trajectories, so the decision
model takes only choices it makes reliably. Be-
low the threshold the LLM decides, so an unsure
answer wastes one cheap decision-model call but
does not risk the task. Thresholds are refitted when
the LLM, decision model or task rules change.
Adapters, serving and accounting. Adapters
ask the same questions inside existing harnesses
through their hooks: strong-or-fast LLM routing
in mini-SWE-agent, guards and triggers in pi, and
command hooks for Codex CLI and Claude Code.
If an adapter or the decision model fails, the har-
ness runs as before (App. Table 9).
5 A GENT DECISION -4B
We train our own decision model for two reasons.
An API model such asJEV is billed per call and can-
not learn a harness’s own rules, and off-the-shelf
models learn from fixed questions and successful
demonstrations. Such data rarely contain the states
an agent reaches after its own mistakes, where a
decision model must also answer (App. D.2). We
therefore post-train a small open model, Qwen3-4B
with LoRA (Yang et al., 2025; Hu et al., 2022), on
states the harness visits: first by supervised fine-
tuning (SFT), then by RL in the agent loop.
Supervised fine-tuning. We run the harness on
587 training tasks and record every decision state
s, 15,694 in all. To include states after errors, a
scripted policy repeats mistakes seen during de-
velopment (Ross et al., 2011; Laskey et al., 2017),
and 30.9% of the states follow a mistake (App. D).

6 Experimental Protocol
Stage 1 tests each delegation alone and keeps those
that are cheaper and non-inferior to the LLM alone.
Non-inferior means that a one-sided test at the 5%
level, on the same tasks run both ways, shows a
loss of less than 3 points in task success (5 on
τ 2-bench; App. E). Stage 2 tests the passing dele-
gations together on new tasks, because delegations
can interact. We pre-registered the models, tasks
and tests, and registered the Stage-2 plan before
reading any Stage-1 result, so that choosing the
combination could not bias its test.
Stage 1: each delegation alone. The decision
model is JEV (and Intern-Decision-4B for three
delegations). The agent LLM is Gemini 3.5 Flash
(Flash) with native tool calls. The cheaper, weaker
Gemini 3.5 Flash-Lite (Flash-Lite) receives routed
steps, simulates the τ 2-bench user and is a second
agent LLM on DECISION GYM (App. F). The LLM
alone and simple controls without a decision model
run on the same tasks as each delegation (App. B.5).
With eleven registered tests, a few could pass by
chance, so Holm’s method (Holm, 1979) makes
each test stricter and keeps the chance of any wrong
pass at 5%. Other results are descriptive.

Stage 2: the delegations together. A script
chose the combination by a rule fixed in advance.
At each decision point it took the delegation that
passed Stage 1 with the largest saving, or kept the
LLM if none passed (App. E). We ran the combi-
nation on 500 new DECISION GYM tasks and on
τ 2-bench telecom tasks. Four Holm-corrected tests
check two things. The first two check that the com-
bination still works. It should be non-inferior to
the LLM alone at lower cost, and cheaper than
its best single delegation without losing success,
or combining would not be worth it. The other
two check that a model we train can take JEV’s
place. On the common states, AGENT DECISION -
4B should beat Intern-Decision-4B, a model of
its size that never saw the agent’s states, and be
non-inferior to its teacher JEV. The combination
should also stay non-inferior to the LLM alone
when AGENT DECISION -4B replaces JEV.

7.1 RQ1: Do isolated scores predict success?
On isolated questions (Figure 4a), JEV was 1.7
points less accurate than Flash at 1/50 of its cost
(App. G.6). On one L4 GPU, AGENT DECISION -
4B and AGENT DECISION -0.8B cost about 4 and
9 times less per decision than JEV (App. G.7). At
the task level, the ranking differed from the iso-
lated one (Figure 4b). StartLux-9B was the most
accurate model on BFCL tool choice (92.2%), yet
it solved only 69.5% of tasks. AGENT DECISION -
4B was less accurate on BFCL (89.3%) but solved
91.5% of tasks, and JEV solved 82.0%. Step-level
accuracy ranked the models nearly as task success
did (Kendall correlation 0.84). The gap lies at must-
ask states, where AGENT DECISION -4B answered
67.4% correctly and JEV answered 58.3%.
Finding 1. Isolated scores misrank decision models.
The best decision model on isolated questions solved
only 69.5% of agent tasks, while AGENT DECISION -
4B solved 91.5%.

7.5 Where delegation fails
Three failure modes recur. A confident wrong
choice at an irreversible step ends the task. All
34 of JEV’s failed tasks began with an irreversible
wrong tool choice, usually cancelling where the
agent should have asked. Models trained on agent
states made no such error (App. G.7). The decision
model can also face a new rule. On hard tasks with
10 customers, AGENT DECISION -4B, trained with-
out this rule, made most cancel-or-ship decisions
but got only 81.6% of them right, and the agent
solved 3.0% of tasks against 88.0% for the LLM
alone. Refitting the threshold restored success with
JEV (Table 1), and retraining AGENT DECISION -
4B on the rule raised its held-out accuracy from
76.5% to 95.3% (App. D.6). Finally, modes that
still call the LLM, such as guards, save little.
8 Related Work
Decision models. JEV and open models like
Intern-Decision, StartLux-Decision and OpenJev
(Almeida, 2026; InternLM, 2026; StartLuxLabs,
2026; razorback16, 2026) score listed options,
while DecisionFlow (Chen et al., 2025) structures
LLM decisions. REFLEX hands an action to the
LLM when its confidence falls below one global
threshold (Wu and Lim, 2026b), and we fit one per
decision point.
Decision evaluation. Decision and tool-use
benchmarks score fixed questions (Benchmark
Heaven, 2026; Ling et al., 2026; Patil et al., 2025;
Ross et al., 2025), and agent environments score
whole episodes (Yao et al., 2025; Trivedi et al.,
2024; Lu et al., 2025). Models with equal scores
can still decide differently (Zhang et al., 2026).
AGENT DECISION BENCH adds step- and task-
level tests.
Routing, deferral and training. Routers and
cascades choose the model for a call (Chen et al.,
2024; Ong et al., 2025; Aggarwal et al., 2024).
Learned routers, compared in LLMRouter (Feng
et al., 2026a), use query–LLM graphs, multi-LLM
logs or multi-round RL (Feng et al., 2025b, 2026b;
Zhang et al., 2025a). A decision model instead
scores listed options and defers if unsure, like learn-
ing to defer (Geifman and El-Yaniv, 2017; Mozan-
nar and Sontag, 2020). Agentic RL trains the LLM
(Jin et al., 2025; Wang et al., 2025d), while we train
the decision model (App. H).
9 Conclusion
Our results support the hypothesis that decision
models help agents when tested, used and trained
inside the agent. Only tests inside the agent
(AGENT DECISION BENCH ) showed which deci-
sion models work there. Trained on the agent’s
states, AGENT DECISION -4B beat JEV inside the
agent and, with thresholds fitted on agent trajecto-
ries (JEVAGENT HARNESS ), made most routine
choices. Models trained this way made the agent
81.1–89.0% cheaper and up to 2.5 times faster,
without losing 3 or more points of success.

Limitations
All tasks and prompts are in English, and most runs
use Gemini agent LLMs, with DeepSeek and Ope-
nAI models in a few. With other languages or agent
LLMs, other kinds of choices may be worth delegat-
ing. Our main tests are non-inferiority tests. They
show that task success drops by less than a fixed
margin (3 points, 5 on τ 2-bench), and showing
equal success would need an equivalence test. The
thresholds and the trained decision model are fitted
to an agent’s own runs, so a new agent, new tools
or a new task family call for refitting the thresholds
and, for the best accuracy, training on that agent’s
states, as we did for ALFWorld. In coding agents,
whose actions are free text, the decision model can
only choose which LLM writes a step. There the
savings were small (7.0–10.5%), and sending the
steps that only read files to a fast LLM gave no
reliable saving, because the decision model could
hardly tell those steps from the others (App. C.3).
Prices and latencies are those we recorded, and
they change with providers, hardware and how the
decision model is served (App. F). We did not com-
pare with learned routers such as RouteLLM on the
same tasks, and GRPO added no measurable gain
over SFT in our runs. In deployment, the share of
answers above the threshold could be tracked to
notice when the tasks drift and the thresholds need
refitting.
Ethical Considerations
We will release the benchmark, harness, recipes,
trained models and data (App. F). Training on JEV
outputs and redistributing derived weights depend
on the provider’s terms, and StartLux-Decision
weights are licensed CC BY-NC 4.0. All bench-
marks are public, and we collect no personal data:
DECISION GYM customers, orders and e-mail ad-
dresses are generated from templates. Lower cost
can make a fast model’s failures on safety-relevant
decisions easy to overlook. With the cheaper Flash-
Lite as agent LLM, the stop guard accepted 40.7%
of the LLM’s own wrong attempts to end the task
(App. Table 7), so a decision-model guard should
never be the only control on an irreversible action.
If an adapter fails, the step runs without it (§4).
Adapters therefore control only cost and speed and
should not be used as security boundaries. We
did not test adversarial observations or policy in-
jection, which can flip a decision model’s typed
answers (Xu et al., 2026; Hu et al., 2026; Wu and
Lim, 2026a), so our results hold for benign states
only. Cheaper agent control also lowers the cost of
misuse at scale.

Compute, Data and AI Use
Compute, software and runs. The open deci-
sion models have 0.8B to 27B parameters, as their
names state, and the API models ( JEV, Gemini,
GPT, DeepSeek) are used through their providers.
We trained and served the open models on cloud
hosts with one NVIDIA L40S, A10G or L4 GPU.
Table 16 gives the GPU hours of each training stage.
Training used PyTorch, Hugging Face Transform-
ers, TRL and PEFT (the StartLux track used Miles),
and serving used vLLM or llama.cpp. Unless a ta-
ble states attempts, each arm ran each task once at
temperature 0, and every number comes from that
single run.
Data and annotation. DECISION GYM tasks,
customers, orders and e-mail addresses are gen-
erated from templates, so the tasks and agent states
we release contain no personal information and no
offensive text. Public benchmark items are used as
distributed. Labels come from DECISION GYM’s
answer key and the benchmarks’ own answers and
checkers, and the τ 2-bench user is an LLM simula-
tor, so no human annotators or study participants
took part.
Use of AI assistants. LLMs play three roles in
this work. They are the objects of study, called
through their APIs in every experiment (agent
LLMs and decision models). JEV and Gemini also
answered agent states to build the training data of
AGENT DECISION -4B (§5). Finally, AI assistants
helped write and test code, check references and re-
vise the writing, under the authors’ direction. The
paper was not generated automatically. The au-
thors designed the study, checked every result and
every sentence, and take full responsibility for the
content.

Deployed thresholds. The registered cascade
tests plug estimates of gd, qL, ∆C and V from
shadow-mode trajectories into Eq. 3. We sort
paired decisions into equal-mass confidence bins
of at least 20 each. ˆτ ⋆ is the lowest confidence
from which every higher bin has a non-negative
estimated advantage, and the harness always defers
if there is none. We set λ = 0 and estimate ˆV as
the success difference between calibration episodes
with every decision at d right and those with one
wrong. For tool selection and arguments the fits
are 1.00 and 0.99 for JEV with Flash (other fits in
results/calibration/).
Registered hypotheses. H1 says that the plug-in
threshold has lower held-out regret than a fixed de-
fault and that recalibration returns over-confident
models to the cost–success front. H2 says that at
a matched firing rate a gate’s gain over a random
gate is proportional to J (Eq. 5). H3 says that
among configurations non-inferior to LLM-only,
those delegating bounded, recoverable, meta-level
decisions dominate the front, and those delegat-
ing copy-dependent arguments or irreversible ac-
tions do not. H4 says that Monte-Carlo targets beat

B.5 Gold Labels, Probes and Measurement
Arms
These definitions were fixed before the main runs.
Labels are computed on a copy of the environment
after the decision model’s answer is recorded and
go only to the decision records. A canary test plants
a gold value and checks that no request contains it.
Verdicts and gold labels. Let D(s) be the num-
ber of steps the answer key needs from a copy of s
to finish successfully (∞ if it cannot within the step
budget, and such doomed states are excluded). We
label an attempt to finish progress if it succeeds,
a wrong answer if everything but the answer is
done, and premature otherwise. Any other call is
fatal if it makes D infinite, progress if it lowers
D, and a detour otherwise. Fatal, premature and
wrong-answer actions are failing. A tool choice is
right if it is an undone plan step that is progress and
whose inputs are visible. An argument is right if
it matches the canonical value (up to case, whites-
pace and 0.01 in amounts), and a guard verdict if
it matches whether the proposal is progress. A re-
flection or routing trigger is right if the next action
without it is failing, a stop trigger if only the an-
swer remains, and a memory write if the text holds
a value a remaining plan step consumes. From its
JSON schema alone, each argument is bounded
(enum, boolean, integer range of at most 20 val-
ues), copyable (numbers, and strings with a format
or pattern or named like an identifier or a quan-
tity) or free. The copy-dependent arguments of H3
(App. A) are the copyable ones.
Measurement arms and probes. Two measure-
ment arms, Flash on 200 tasks and Flash-Lite on
500, act like LLM-only while every gate runs in
shadow, so its label is observed at every state. On
Flash-Lite, one-step branches replay states with the
intervention and with a placebo that only resam-
ples the default call. Relative to the placebo, e is
the gain in the chance of progress when the trigger
fires before a failing action, and h is the gain in the
chance of failure when it fires before a progress ac-
tion. A probe is a proposal the guard scores but that
is never executed (Table 7), and probes enter no
reported success, cost, test or training data. A gate
cell is estimable for H2 when its arm has at least
30 positive and 30 negative labels and a live and
a matched-rate random arm exist. The reflection-
trigger test has no headroom when, at W = $1 ,
the 95% CI of its one-step perfect-information ceil-
ing (Eq. 5 with J = 1 and the measured e + h)
lies within ±3.3 points, the registered minimum
detectable effect.

D.5 A Sub-1B Decision Model with a Scoring
Head
We gave Qwen3.5-0.8B a fresh scoring head of
the Clef design (Cloudflare, 2026), which returns
one logit per allowed option for every question
of a request in one pass, and trained it with
LoRA and Unsloth’s recipe (Unsloth AI, 2026) on
AGENT DECISION -4B V1’s supervised data (arm
A) or on Unsloth’s public mix of classification and
typed-decision data (arm G), or on both (arm AG).
Arm A matched AGENT DECISION -4B V1 on the
common states (Table 18). Arm G matched arm
A on BFCL’s tool choices but scored 75.3 points
lower on the common states. Arm A’s confidences
sat close to 1, and the registered fit placed both
thresholds within 10−9 of 1. In the final harness
(App. C.1) arm A solved 100.0% of 200 tasks, as
the 4B harness did, at 64.2% lower cost than Flash
alone. Unsloth’s decision-model code is AGPL-3.0,
and we redistribute none of it.
D.6 D ECISION GYM-Hard
DECISION GYM-Hard keeps the frozen generator,
serves 10 or 12 customers per task and adds a tier
rule that decides from the customer’s tier and the
order amount whether each order is cancelled or
shipped (Table 19). With Stage 2’s combination
JEV kept success at a small saving but was slower,
and AGENT DECISION -4B V1, which had never
seen the tier rule, took nearly every cancel-or-ship
decision, was often wrong and lost most tasks. Af-
ter refitting, the threshold left every tool choice of
AGENT DECISION -4B V1 to the LLM, and JEV’s
refitted cascade kept success at lower cost once
the final answer listed each customer. One more
epoch on tier-rule states raised AGENT DECISION -
4B V1’s held-out cancel-or-ship accuracy from
76.5% to 95.3% and kept its common-state accu-
racy (99.1% against 99.2%). In the agent it ac-
cepted no wrong cancel-or-ship decision, but the
paired test did not establish non-inferiority at the
3-point margin (Table 30). As registered, its last
120 tasks were added after the first 80 had been
read.

E Protocol and Statistics
Metrics. Every success number comes with dol-
lars, latency (the critical path of model calls)
and LLM calls, as in cost-aware evaluation of
agents, routers, calibration and selective prediction
(Kapoor et al., 2025; Yao et al., 2025; Ong et al.,
2025; Pakdaman Naeini et al., 2015; Geifman et al.,
2019). Utility is U = W S− C − λL for success S,
cost C, latency L, task value W and latency price
λ, and ECE is the 10-bin top-label calibration er-
ror (other metrics in docs/BENCHMARK_SPEC.md).
Paired comparisons resample tasks and keep the
trials of one task together (Efron and Tibshirani,
1993; Koehn, 2004). A task that still errors in either
arm after two retries leaves that comparison.
Non-inferiority decision rule. For margin m on
a paired binary endpoint, W and L count the tasks
the arm wins and loses. The outcomes (W, L) are
ordered by the monotone hull of the log p-value
of Tango’s one-sided score test of H0: ∆ ≤ −m
(Tango, 1998). The decisive p is min{1, γ+ U },
where U bounds the tail probability under every
boundary null whose discordance lies in a (1 −
γ) Clopper–Pearson set ( γ = 10 −4, Suissa and
Shuster, 1985; Berger and Boos, 1994). The test is
valid at every n, with exact size at most 0.997α at
the registered sizes. At zero discordance we report
the exact upper bound 1 − α1/n on the loss rate.
Other tests. The tool cascade, the three-tool
shortlist and the stop veto must hold for both
JEV and Intern-Decision, so their decisive p is
max(pJEV, pIntern) (Table 25). Superiority pri-
maries use the exact conditional test on discor-
dant pairs and, for the reflection trigger, the one-
sided paired t-test of the per-task utility differ-
ence. Sign-flip tests and the paired task bootstrap
(B = 10,000) are descriptive. On τ 2 the per-task
endpoint is majority pass over three attempts, and
the transfer test refits ˆτ ⋆ on 15 held-out airline
tasks, counting a decision as right if it matches the
next reference action. Pilots on retired seeds fixed
the suite settings, and no pilot result is reported as
a finding. The Flash-Lite pairs and the τ 2 transfer
test are underpowered and can end inconclusive
(exact power in results/reviews/2026-10-02/
ni_power_exact_r8.md).

G.9 A Shifted DecisionGym Split
DECISION GYM-Shift† renames every core tool and
the clarification tool, rewords the requests, the pol-
icy line and the customer’s replies, and doubles
the distractor tools (129 options per tool choice
instead of 69). It adds must-ask states and three
plan shapes the training generator never produces:
asking twice, a request that becomes ambiguous
only after a lookup, and a confirmation message
after shipping. The common states are 1,250 states
of 100 shifted tasks, and live runs use 200 further
tasks.
The 4B models trained on the generator lost lit-
tle and stayed ahead of every off-the-shelf model
at both levels (Table 39). The 0.8B head did not
carry over. With the old names and wording re-
stored it answered 95.1% of the same states, so it
had learned the generator’s names more than the
decisions.
The confidence gate under shift. We ran the fi-
nal harness†, which takes a decision only when the
model’s confidence clears its threshold, on the same
200 shifted tasks with each model’s in-domain
thresholds (Table 40). The two 4B models stayed
confident and kept taking most tool choices, so
success fell. Only the 0.8B head’s learned defer-
ral handed choices back, and non-inferiority was
shown for none of the three.

H Extended Related Work
Decision models. Beyond §8, JEV has served
as REPLACE for action-only and memory control
(Ma et al., 2026; Jiang et al., 2026) and as a judge
or monitor (Guo et al., 2026b; Kwartler et al.,
2026). Studies examine its calibration and robust-
ness (Deußer et al., 2026; Wu and Lim, 2026a).
Closest to us, JEV-as-a-Judge fits an acceptance
threshold on about 100 local labels (Li et al., 2026),
and REFLEX escalates agent actions below one
global threshold, an action-level CASCADE (Wu
and Lim, 2026b). We compare decision points
and modes under one cost ledger, set thresholds
by price, and test the chosen combination and a
post-trained model on new tasks.
Routers, cascades and deferral. Cascade rout-
ing (Dekoninck et al., 2025), agentic routers (Liu
et al., 2026) and fast–slow controllers (Yang et al.,
2026; Zhang et al., 2025b) decide which model or
how much thinking a step gets. JEV and LLM
judges err on the same items, so a cascade be-
tween them mainly saves cost (Rao and Callison-
Burch, 2026). Agents also ask for help through
uncertainty-aware deferral (Piatrashyn et al., 2026)
or conformal prediction (Ren et al., 2023), and
finite-sample risk control (Angelopoulos et al.,
2024) could replace our plug-in thresholds, and
serving systems such as vLLM (Kwon et al., 2023)
lower the price of each call. Tool retrieval (Patil
et al., 2024) isASSIST with a similarity scorer, as in
our BM25 control (Robertson and Zaragoza, 2009),
and reflection (Shinn et al., 2023) is a TRIGGER
decision in our terms.
