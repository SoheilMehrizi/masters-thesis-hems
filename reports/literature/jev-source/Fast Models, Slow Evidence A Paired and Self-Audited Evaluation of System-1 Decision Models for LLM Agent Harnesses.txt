Fast Models, Slow Evidence:
A Paired and Self-Audited Evaluation of System-1 Decision Models for
LLM Agent Harnesses
Jiawei Li
Abstract
Agent harnesses make many small, typed de-
cisions per task: which model to call, which
tool to use, whether retrieved text is relevant,
whether an input carries an injection.System-
1 decision modelsanswer such questions in
a single forward pass with class probabili-
ties, promising large cost and latency savings
over LLM calls. We present a paired evalua-
tion of an open-weight (LAYA) and a hosted
(JEV) System-1 model on 11 agent decision
points built from 18 public sources: 7,283
base cases plus 6,640 robustness variants, with
byte-identical inputs, paired tests, and cross-
hardware and cross-day reproducibility checks.
JEVis significantly more accurate on 9 of 11
decision points (+10.8 to +46.0 pp). Neither
model beats chance on zero-shot model rout-
ing, and they tie on RAG relevance gating.
LAYAchanges 30% of its answers when the
option order is reversed and degrades sharply
with many or similar candidates (31% at 50
nearest-neighbour tools, vs. 98% for JEVon
items with a unique correct tool). We also au-
dit our own pipeline. Three analysis errors
and one design confound distorted headline de-
ployment claims: an omitted pre-screen cost
(reported 23.9% saving, actual 4.3%), gate ac-
curacy reported as end-to-end quality (58%
vs. 98%), in-sample thresholds (5% target, up
to 17% held-out misses), and a “channel ef-
fect” on injection false positives that vanishes
with channel-native content. Two other sus-
pected confounds did not change the conclu-
sions. All cases, raw outputs and analysis
code are available at https://github.com/
David-DL-Space/sys1-eval.
1 Introduction
An LLM agent is surrounded by aharness: code
that routes requests, selects tools, decides whether
to call a tool at all, gates retrieval, and screens
untrusted content. Each of these is adecision: a
typed output from a small, known set. Most of
them are currently made by prompting the same
LLM that does the work, which spends hundreds
of milliseconds and a full generation on a problem
whose output is one of a few labels.
A recent class of models targets exactly this
layer. Following Kahneman (2011), their ven-
dors call themSystem-1models: given astate
and a set of typedquestions( choice among K
options, a yes/no probability, or an ordinal score),
they return a distribution over answers in one non-
autoregressive pass. LAYA(Laya AI, 2026) ships
open weights; JEV(TypeSafe AI, 2026) is a hosted
API. Both claim LLM-level accuracy on structured
decisions at a small fraction of the cost.
Practitioners who want to adopt such a model
need answers to three concrete questions.(RQ1)
At which harness decision points is a System-1
model accurate enough?(RQ2)How reliable is
it: stable under option order, wording, input chan-
nel, and model version, and calibrated enough to
threshold?(RQ3)When used as agatein front of
an LLM, what does it actually save, and at what
risk?
We answer these with a paired evaluation (§3)
and make three contributions:
• A decision-point benchmark for agent har-
nesses.It has 11 decision points, from model
routing to PII egress, built from 18 public sources,
with byte-identical inputs to both systems and
paired statistics (§4).
• Findings for practitioners(§5, §6). JEVdom-
inates on tool selection, large label sets and in-
jection screening. Both systems fail at zero-shot
routing and tie on RAG gating. LAYAis order-
sensitive, collapses with similar candidates, and
misses half of the injections embedded in docu-
ments. Used as gates, System-1 models save far
less than naive accounting suggests.
• A self-audit of the evaluation itself(§7). The
first version of this study contained errors that
changed deployment recommendations. We

2 Related Work
Decision layers in agents.Cost-aware routing
and cascades send easy queries to cheaper mod-
els (Chen et al., 2023; Ong et al., 2024). Router-
Bench provides per-query outcomes of many LLMs
for studying such routers (Hu et al., 2024). Tool
use is evaluated by BFCL, includingirrelevance
cases where no tool should be called (Patil et al.,
2023, 2025). Adaptive retrieval decides when to re-
trieve or trust context (Asai et al., 2024; Yan et al.,
2024; Jeong et al., 2024). Safety classifiers such
as Llama Guard screen inputs and outputs (Inan
et al., 2023). All of these are typically implemented
either as a trained task-specific classifier or as an
LLM prompt. System-1 models sit in between: one
general model, zero-shot over typed questions.
Prompt injection.Indirect prompt injection
places adversarial instructions in data that the agent
retrieves (Greshake et al., 2023). AgentDojo, In-
jecAgent and BIPIA evaluate agents and defenses
under such attacks (Debenedetti et al., 2024; Zhan
et al., 2024; Yi et al., 2023). We evaluate thedetec-
torin isolation and study how the delivery channel
interacts with content style.
Evaluation methodology.We use paired tests
(McNemar, 1947; Dror et al., 2018), Wilson inter-
vals (Wilson, 1927), calibration metrics (Guo et al.,
2017; Platt, 1999), and selective-prediction views
of thresholding (Geifman and El-Yaniv, 2017). Or-
der and wording sensitivity of LLM classifiers is
well documented (Zheng et al., 2024; Pezeshkpour
and Hruschka, 2024; Sclar et al., 2024). So are
label errors in test sets (Northcutt et al., 2021),
contamination of public benchmarks (Sainz et al.,
2023), and the limits of LLM judges (Zheng et al.,
2023). Our self-audit adds a less discussed failure
class: errors indeployment accounting(cost, end-
to-end quality, threshold selection) that sit down-
stream of correctly scored predictions.
3 Systems and Protocol
Interface.Both systems accept astate(here
always a string) and a dictionary ofquestions.
A choice question has instructions and a
criteria map from option keys to short descrip-
tions. A yes/no question ( noul in both APIs) re-
turns p(yes). We use score questions only as aux-
iliary signals. LAYA0.3.21 routes each request to
an English or a multilingual checkpoint. JEVre-
turned the version string jev-1.13.0 on every call
we made, across two days.
Fairness protocol.Both systems receive byte-
identical state and questions for every case.
Confidence is maxk pk for choice and max(p,1−
p) for yes/no. This follows LAYA’s own calibration
code. Its response field confidence is an entropy-
based quantity on a different scale: it differs from
maxk pk by 0.299 on average, versus 0.010 for JEV.
Using that field would silently break any threshold.
Accuracy intervals are Wilson; model comparisons
use the exact McNemar test on discordant pairs,
with an asymptotic CI for the paired difference.
We do not correct for multiplicity. Every claim
of a difference below has p <0.001, and we call
p >0.4a tie only where the CI is narrow.
Determinism and reproducibility.Re-running
420 cases, LAYAchanged 0 decisions and JEV
changed 1. On a second machine (Apple M4
CPU vs. an RTX 2080 Ti GPU), LAYAreproduced
1,180/1,180 decisions (max |∆p|= 0.006 ). One
day later, JEVchanged 5 of 1,080 decisions (0.5%).
Pairing runs across days and machines is therefore
safe for both systems.
Reference LLM.For the control experiments
(§7) we add DeepSeek-V4.1-Flash (DeepSeek,
2026) as a reference. It is prompted with the
same state and question (temperature 0; prompt
in App. B). It isnotpart of the paired comparison:
its input format necessarily differs.

(p50) from one client site and 83 ms from another.
The “10× faster” comparison that the first version
of this study reported was a property of one net-
work path. JEVuses 759 tokens per decision on av-
erage, i.e. ≈$32 per million decisions at $0.042/M
tokens. LAYA’s marginal cost is local compute.
6 Using System-1 Models as Gates
Agatedecides whether an expensive path (an LLM
call, a review, a block) runs. Two quantities matter:
the share of traffic that still takes the expensive path
(call rate), and the share of cases that needed the
expensive path but skipped it (miss rate, FNR).
RAG gating saves little because of base rates.
If the gate skips generation when context is judged
irrelevant, then at a 5% miss budget LAYAkeeps
92.4% of LLM calls and JEV79.8% (Fig. 4a). End-
to-end, 97.9% of answerable queries are still an-
swered by both (assuming the LLM is right). The
first version of this study reported 45.1%/57.7%
here, which is the gate’s own classification accu-
racy (see §7). The binding constraint is instead
the ceiling on savings, which is set by the share
of irrelevant retrievals in traffic. In our set a per-
fect gate saves at most 58%. Our mix is synthetic,
so absolute savings will differ in production. The
ranking will not: JEV’s AUROC is 0.71 vs. 0.61.
On real top-5 contexts (400 cases), both systems
recognise under 40% of “no answer here” contexts,
which makes a skip-gate unsafe. We recommend
using the gate as atrigger for more retrieval, not
as a skip.
Thresholds must be chosen out of sample.Pick-
ing the threshold that meets a 5% FNR on the same
data it is evaluated on guarantees 5% by construc-
tion. When the threshold is picked on one half and
evaluated on the other (Fig. 4b), the median FNR
stays near 5%, but the 95th percentile is 6–8% for D
(npos=800) and 10–17% for the 100–200-positive
tracks. The target is exceeded in roughly half of all
splits. A 5% promise needs either several hundred
positives for calibration or a conservative margin.
Two-tier safety review.Track S asks whether a
System-1 pre-screen can spare an LLM reviewer
(DeepSeek-V4.1-Flash) from seeing clearly benign
requests. Gold labels come from a written policy
applied by a different LLM (GLM-4.6; App. D).
This gold agrees with the dataset labels on only
72.8% of 540 items. At τ=0.1, the JEVpre-screen
sends 65.6% of traffic to the reviewer with an iden-
tical in-sample miss rate (11.6%). Once the pre-
screen’s own tokens are counted, however, the cost
falls by only 4.3% (Fig. 5). At τ=0.05 the two-tier
system costs 4.7%morethan the reviewer alone.
The LLM reviewer here is cheap ($72 per million
requests, batched); a single System-1 call is 20% of
that. The durable benefit islatency: 34–41% of re-
quests are released in about 0.3 s instead of waiting
for a multi-second LLM review. With thresholds
chosen on held-out halves, the pre-screen adds at
least one extra miss in 47% of splits. LAYAis use-
less as a pre-screen: it must pass 99.3% of traffic
to preserve recall.

The first version of this study was built quickly,
and its reports were confident and detailed. We
re-derived every number from raw outputs and de-
signed a control experiment for every suspected
confound. Table 2 lists what changed.
Control G2: channel vs. content.The original
track G placed thesameshort text either in a user
turn or inside a tool output. Benign texts were
user queries (“Unemployment young people Eu-

of read_email. In the control, we take 120 pas-

90.8–93.3% of embedded payloads.

8 Threats to Validity
Label noise.A blind LLM judge (DeepSeek-
V4.1-Flash, given neither the gold label nor model
outputs) re-labelled a stratified sample of 360 cases.
It agrees with the dataset on 90.0% of items that
both models got right, 75.7% of disagreements, and
only 12.7% of items that both got wrong. Chang-
ing the judge instruction from “strict” to “lenient”
reading flips 28.1% (32/114) of the re-judged both-
wrong labels. This is mostly because BEIR rele-
vance is broader than “answerable”, so absolute
accuracies on D (and I) are underestimates. On
disagreements the judge sides with JEVin 131 of
145 decided cases. We donottreat that as inde-
pendent confirmation: judge and JEVmay share
systematic preferences. The ranking claims rest on
the gold labels and on the robustness of the ranking
to wording.
Routing labels.79% of A items come from
multiple-choice benchmarks, and 95% have binary
per-item outcomes from a single run of each model.
Whether a 7B model “solves” a four-way multiple-
choice item is partly a coin toss, so A’s attainable
accuracy is unknown. Our routing result says that
zero-shot System-1 routing failson these labels. It
does not measure the limit of routing in general.
Contamination and scope.All sources are pub-
lic, and JEV’s training data is not. Near-perfect
scores on popular sets (B, E) may partly reflect
exposure. The G2/B2/J2 controls use newly com-
posed inputs and preserve the conclusions, which
is some reassurance. We tested one version of
each system, English-centric decisions (multilin-
gual cells have n=10), and zero-shot use only.
LAYA’s fine-tuning path, its main selling point for
domain adaptation, is not evaluated, and neither is
its typed-decisions checkpoint, which crashed on
our GPU. On the 100-case pilot, run on CPU, that
checkpoint matched the default router within one
point (59% vs. 58%).
Audit coverage.We fixed every error we
found, but an audit only covers the ques-
tions its auditor thought to ask. We re-
lease every raw response (https://github.com/
David-DL-Space/sys1-eval ) so that others can
extend it.
9 Recommendations and Conclusion
For harness builders:
• Use a strong System-1 model (here JEV) for tool
selection, large-label intent classification, injec-
tion screening of tool outputs, and groundedness
checks. These are single-glance decisions over a
closed set, and it is near LLM quality on them.
• Do not use zero-shot System-1 models to route
between LLMs, to skip generation on RAG rele-
vance, to screen PII, or as the only safety gate.
• If you use LAYA, keep K≲10 dissimilar op-
tions, fix the option order or vote over permuta-
tions, compute confidence as maxk pk, and recal-
ibrate per domain.
• Report gates by call rate andheld-outmiss rate.
Include every component’s cost. Test channel
effects with content that is native to each channel.
System-1 models make agent decisions cheap.
Evaluating them turned out to be the harder part:
in our study, the errors that changed recommenda-
tions sat in the accounting around the model, not
in its scored predictions.
Limitations
We evaluate two systems at single versions, zero-
shot, on public English-dominant data with syn-
thetic class mixes. Absolute accuracies carry a
±5 pp wording band, and gate savings depend on
production base rates that we do not observe. La-
tency was measured from two client sites and on
two hardware types only. Safety and PII gold labels
involve LLM annotators whose policies differ from
dataset conventions (72.8% agreement). The LLM
reference receives a necessarily different prompt
format and is not a paired competitor. The LAYA
fine-tuning path is untested.
Ethics Statement
We use publicly released datasets under their li-
cences. Harmful-request datasets (BeaverTails,
HarmBench, Do-Not-Answer) and jailbreak pay-
loads are used only as classifier inputs; no harmful
completions were generated. The PII dataset is
synthetic. API keys were read from local files and
never written to logs or outputs.
